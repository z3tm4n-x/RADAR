# Стенд сравнения `b_c(He)` для компоненты НЭК

## Назначение и границы

Стенд сравнивает напечатанное в ОСТ значение
`b_c(He) = 6,6·10^-2` и инженерную альтернативу `6,6·10^-3`.
Он рассчитывает только дифференциальный направленный поток
компоненты **НЭК He**:

`F(E,W) = a_c · exp(b_c · W) · E^[-(a_g - b_g · W)]`.

Главная компонента ГКЛ, АКЛ и суммарный спектр в стенде не
используются. Единицы результата:
`cm^-2 s^-1 sr^-1 (MeV/nucleon)^-1`.

Энергии зафиксированы: 10, 30, 100 и 300 МэВ/нуклон. Числа Вольфа
задаются явно при каждом запуске.

COSRAD здесь является независимой расчётной реализацией, а не эталоном
физической правильности. Совпадение с ним не подтверждает автоматически
формулу ОСТ, исправление опечатки или допуск к нормативному выпуску.

## Запуск без данных сравнения COSRAD

Из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m radar.gcr.nek_he_bc_validation --wolf 0 30 60 100
```

Отчёт содержит оба потока и их взаимные отношения. Поле
`cosrad_comparison` будет `null`: без внешних точек стенд не ранжирует
кандидатов. Производственный коэффициент стенд не выбирает в любом случае.

## Формат данных сравнения COSRAD

Данные принимаются только в JSON с обязательными метаданными:

```json
{
  "metadata": {
    "cosrad_version": "4.3.1.1",
    "source_artifact": "isolated_nek_he_export.csv",
    "source_sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
    "calculation_configuration": "NEK He; W=0,30,60,100; E=10,30,100,300 MeV/n",
    "exported_at_utc": "2026-08-11T09:00:00+00:00",
    "component": "ost_nek_he_only",
    "units": "cm^-2 s^-1 sr^-1 (MeV/nucleon)^-1"
  },
  "points": [
    {
      "wolf_number": 0.0,
      "energy_mev_per_nucleon": 10.0,
      "flux": 0.0001277328201240871
    }
  ]
}
```

`source_artifact` должен указывать на реальный исходный экспорт COSRAD: абсолютным
путём либо путём относительно JSON-файла. Перед сравнением стенд самостоятельно
вычисляет SHA-256 этого файла и требует точного совпадения с `source_sha256`.
Одной декларации контрольной суммы в JSON недостаточно.
Проверка хеша удостоверяет неизменность файла, но сама по себе не доказывает,
что вручную перенесённые точки соответствуют его содержимому, что компонента
НЭК действительно выделена и что расчёт COSRAD физически правилен. Эти
проверки происхождения и преобразования данных должны быть отражены в
протоколе сравнения отдельно.

Массив `points` должен содержать по одной точке для каждой комбинации
запрошенного числа Вольфа и четырёх фиксированных энергий. Неполная
или лишняя сетка отклоняется. Нулевые и отрицательные потоки не
принимаются.

Запуск с данными сравнения:

```powershell
.\.venv\Scripts\python.exe -m radar.gcr.nek_he_bc_validation `
  --wolf 0 30 60 100 `
  --cosrad-reference .\cosrad_nek_he_reference.json
```

Для каждого кандидата стенд выводит среднее, среднеквадратичное и
максимальное относительное расхождение с COSRAD. Сохранённые имена полей
`error` и `selection_status="selected"` относятся только к этому численному
ранжированию, а не к установленной ошибке RADAR или утверждению коэффициента.
`best_candidate` означает ближайшее совпадение с переданным набором данных
по минимуму среднеквадратичного расхождения. При равенстве метрик ближайший
кандидат не выделяется. Даже при очень плохом совпадении обоих вариантов
один может оказаться численно ближе: это не критерий принятия.

В сериализованном отчёте и в блоке сравнения ограничения заданы явно:

- `evidence_role="independent_model_comparison_only"`;
- `normative_qualification="not_established"`;
- `coefficient_change_authorized=false`;
- в блоке сравнения: `best_candidate_meaning="closest_match_only"`.

Эти поля не принимаются как входные параметры и не могут быть заменены
посредством обычного изменения неизменяемой структуры отчёта. Они не являются
системой прав доступа: они фиксируют предел доказательной силы результата.

## Важно

Результат стенда сам по себе **не меняет**
`OST_NEK_HE_BC_USED`. Для изменения нужны проверка первоисточника модели,
формулы и единиц, разбор расхождения и отдельно зафиксированное обоснованное
решение. Одного совпадения с COSRAD недостаточно. До такого решения модель использует
напечатанное в ОСТ значение `6,6·10^-2` со статусом
`pending_cosrad_comparison`.

Приложенная пользователем статья COSRAD не содержит значения `b_c(He)` и
не разрешает спор между `6,6·10^-2` и `6,6·10^-3`. Её утверждения и границы
сопоставимости с текущей локальной программой разобраны в
`stage4_data_provenance.md`, раздел «COSRAD article and comparison policy».
