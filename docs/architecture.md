# Архитектура RADAR

## 1. Общий принцип

RADAR строится как расчетный комплекс с разделением на:

1. расчетное ядро;
2. слой данных;
3. слой экспорта;
4. пользовательский интерфейс.

Пользовательский интерфейс не должен содержать физических формул, нормативных таблиц и расчетной логики.

## 2. Базовые методические решения

- Основной профиль: ОСТ 134-1044-2007.
- САС: только целое число лет.
- Доза: рад.
- Kp по умолчанию: 3.
- Защита: сферическая алюминиевая.
- Электроны ГКЛ в первой версии не рассчитываются.
- Тормозное излучение электронов ЕРПЗ учитывается.
- Протоны входят в LET/ЛПЭ-расчет для SEE.
- SEE рассчитывается по методике исходного прототипа RADAR.
- Экспорт требований: только XLSX.
- Графики в XLSX-файл требований не добавляются.

## 4. Расчетное ядро

Расчетное ядро должно:

1. не зависеть от GUI;
2. принимать типизированные входные данные;
3. возвращать типизированные результаты;
4. не читать таблицы при импорте модулей;
5. использовать numpy/scipy для численных расчетов;
6. использовать pandas только для импорта, экспорта и отображения таблиц.

## 5. Слой данных

Нормативные и расчетные таблицы должны храниться отдельно от кода.

Каждая таблица должна иметь паспорт:

- название модели;
- нормативный документ;
- приложение;
- номер таблицы;
- единицы измерения;
- дата переноса;
- статус проверки;
- контрольные значения.

## 6. Слой экспорта

Экспорт требований выполняется только в XLSX.

Экспортер получает готовый объект результата и не выполняет физические расчеты.
